# 테스트 기록

소비자 앱에서 직접 해 본 것만 적는다(API와 동작이 다르다). 확인한 것과 추정을 섞지 않는다.

## 기록 형식

| 날짜 | 앱 (버전/요금제) | 대상 주소 | 전달 방식 | 입구 읽음 | 조각 링크 따라감 | 지어내기 | 경계 지킴 | 메모 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |

전달 방식: (a) 링크 전달 (b) 안내판 사진 전달.

## 배포 직후 확인할 것

- [x] **사진 속 주소를 여는가 (최우선).** → 세 앱 모두 열지 않음 (2026-09-20 기록 참고). 원래 항목: 안내판 사진만 보냈을 때 각 앱이 주소를 여는가, 거부하는가(Claude: `url_not_in_prior_context` 가능성), 경고를 띄우는가(ChatGPT: "확인되지 않은 링크"). 실패하면: 이름으로 검색해서 찾아가는가, 손님이 주소를 직접 치면 되는가
- [ ] 색인 전과 후의 차이. 배포 당일과 검색엔진에 잡힌 뒤를 나눠 기록
- [ ] 무료 요금제에서 링크 열기가 되는가 (앱별)
- [ ] 국내 앱(뤼튼, 클로바X, 에이닷, 카나나)이 건넨 주소를 읽는가 — 조사로는 정보를 찾지 못함
- [ ] 같은 주소의 내용을 바꾼 뒤 다시 물었을 때 옛 내용(캐시)이 나오는가, 얼마나 오래
- [ ] **호스트가 AI를 막지 않는가.** ChatGPT·Claude·Gemini 앱에 주소를 건넸을 때 실제로 열리는가. 안 열리면 호스트/CDN의 AI 트래픽·봇 설정부터 본다 (CONTEXT 3.2b)
- [ ] 영어 간판에 한국어로 물었을 때 답의 품질 (번역은 손님의 AI가 한다는 주장의 확인)
- [ ] `.md` 사본이 `text/markdown` 으로 나가는가. 어느 앱이 `.md` 를 청하는지 서버 로그로 볼 수 있는가
- [ ] 새로 만든 도메인(색인 안 됨)의 주소를 각 앱이 여는가
- [ ] 입구만 건넸을 때 조각을 스스로 여는가 (읽은 페이지에 등장한 링크만 여는 앱이 있는지)
- [ ] 간판에 없는 것을 물었을 때("주인 연락처?") 지어내지 않는가

## 기록

### 2026-09-20 — 배포 (GitHub Pages, ganpan.org, Cloudflare DNS only)

서버 쪽 확인. curl 로 직접 본 것이며 AI 앱 테스트는 아직이다.

- DNS: A 레코드 4개가 GitHub Pages IP로 풀린다. Cloudflare 프록시 꺼짐(응답 IP가 GitHub 것).
- `/ganpan/what` 처럼 확장자 없는 조각 주소: 200.
- `.md` 사본: 200, `text/markdown; charset=utf-8`.
- `/sitemap.xml`, `/robots.txt`: 200.
- **입구 리다이렉트:** `ganpan/index.html` 만 있을 때 `/ganpan` 은 `/ganpan/` 로 301. 같은 내용을 `ganpan.html` 로도 내자 `/ganpan` 이 리다이렉트 없이 200 (`/ganpan/` 도 200). GitHub Pages에서는 `<dir>.html` 이 디렉터리보다 먼저 잡힌다. 다른 호스트에서는 미확인.
- HTTPS 인증서: DNS를 넣기 전에 커스텀 도메인을 먼저 등록했더니 발급이 시작되지 않았다(기본 github.io 인증서가 나옴). Pages 설정에서 도메인을 뺐다가 다시 넣자 곧바로 승인·적용됨. 이후 HTTPS 강제를 켰고 http 는 https 로 301. **순서는 DNS 먼저, 도메인 등록은 그다음.**

### 2026-09-20 — AI 앱 테스트 1차 (작성자 직접, 폰)

대상: https://ganpan.org/ganpan (배포 당일, 검색 색인 전). 앱: ChatGPT, Claude, Gemini. 버전·요금제는 미기록.

| 항목 | 결과 (세 앱 공통) |
| --- | --- |
| 안내판 사진만 전달 (주소 전체가 사진에 글자로 있음) | **열지 않는다.** 전체 링크가 사진에 있어도 마찬가지 |
| 사용자가 주소를 채팅에 글자로 입력 | **연다** |
| 입구를 연 뒤 조각(`/ganpan/what` 등) | 추가 조작 없이 바로 연다 |

해석:
- 앱들은 "사용자가 글자로 건넨 주소"와 "그 주소에서 읽은 페이지에 나온 주소"만 연다. 사진에서 AI가 읽어 낸 주소는 사용자가 건넨 것으로 치지 않는다. CONTEXT 3.2c에서 문서로 본 규칙이 소비자 앱에서도 그대로였다.
- 입구 하나만 사용자의 손으로 건네면 그 아래는 전부 열린다. 입구 + 조각 + 절대 URL 구조는 이 규칙과 잘 맞는다.
- 2026-03 Proxy_AIArt 때와 정책이 달라졌다. 지금의 신뢰 기준은 "누가 그 주소를 말했는가"다.
- **병목은 하나: 손님이 입구 주소를 글자로 보내게 만드는 것.**

미기록(다음에 볼 것): 사진을 받았을 때 각 앱이 뭐라고 답하는가(주소를 글자로 되돌려 주는가, 복사하기 쉬운 형태인가), ChatGPT의 "확인되지 않은 링크" 경고 여부, `https://` 없이 `ganpan.org/ganpan` 만 쳐도 여는가, 영어 간판에 대한 한국어 답의 품질, 경계 문장을 지키는가.

추가 (같은 날, 작성자 확인): **Gemini는 `https://` 까지 붙은 전체 주소를 보냈을 때만 연다.** `ganpan.org/ganpan` 처럼 도메인부터 친 것은 열지 않는다. ChatGPT·Claude에서 스킴 없는 주소가 되는지는 미기록.

→ 안내판에는 주소를 `https://` 부터 전부 인쇄한다. 폰에서 그걸 손으로 치기는 번거로우므로, 주 경로는 "사진 → AI가 주소를 글자로 적어 줌 → 복사해서 다시 보냄", 직접 입력은 보조 경로로 둔다.

### 2026-09-20 — 결정: 안내판은 "주소를 입력하세요"

사진 경로는 접는다. "사진 → AI가 주소를 글자로 적어 줌 → 복사해 다시 보냄"과, AI가 주소를 코드 블록으로 주게 하는 문구(손님에게 하는 말 속에 / AI에게 드러내 놓고)까지 후보로 만들었으나, 작성자 판단: 이미지로는 도저히 안 되고, 주소를 치는 것이 어렵지 않다. 앱이 믿는 것은 어차피 손님이 직접 친 주소뿐이다.

- 문구: "AI 채팅창에 이 주소를 입력하고 물어보세요." + `https://` 부터 전부 인쇄한 주소.
- 인쇄용 견본: `docs/placard.html`
- 남은 확인: ChatGPT·Claude에서 `https://` 없이 쳐도 열리는가(Gemini는 안 됨). 사람들이 실제로 주소를 치는가(현장에서만 알 수 있음).

### 2026-09-20 — 기록 정정과 추가 관찰 (작성자)

앞의 기록을 바로잡는다.

- **사진 경로는 "안 된다"가 아니라 "경험이 나쁘다".** 사진을 받은 AI는 이미지 속 글자를 프롬프트 인젝션일 수 있다고 보고 곧바로 경계하며, 왜 조심하는지를 구구절절 설명한다. 거기서 간판을 여는 데까지 갈 수는 있으나 UX로는 최악. **같은 주소를 직접 입력해 들어가면 AI가 아주 친절해진다.** 같은 내용인데 들어온 경로에 따라 태도가 달라진다.
- **"입구를 연 뒤 조각은 세 앱 모두 바로 연다"는 틀렸다.** ChatGPT는 그 뒤에도 손님이 조각의 전체 주소를 보내 줘야 그 내용을 알려 준다. Claude·Gemini는 스스로 연다.

→ 대응: 입구에 조각 주소를 코드 블록 안에 한 줄씩 적는다(복사 버튼). AI 앱들이 어떻게 여는지를 사실로 서술한 짧은 절을 입구에 둔다. AI에게 하는 명령은 넣지 않는다. (SPEC 5.1, 5.3)

다음에 볼 것: 이렇게 바꾼 입구를 ChatGPT에 건넸을 때 (1) 조각 주소를 코드 블록으로 되돌려 주는가 (2) 손님이 그것을 복사해 보내면 조각을 여는가 (3) 서술 절 때문에 경계하는 역효과는 없는가.

### 2026-09-20 — 추가 관찰과 입구 개정 (작성자)

- ChatGPT는 한 메시지에 조각 주소 여러 개를 함께 담아 보내도 각각 잘 읽는다.
- 손님이 "복사하기 편하게 코드블록으로 감싸서 줘"라고 말하면 AI가 주소를 코드 블록으로 준다(손님 자신의 말이므로 당연히 따른다).

→ 입구 개정: 조각 주소 전부를 코드 블록 하나에 모음 + "Owner's request to the guest's AI" 한 문장(출처를 드러낸 부탁).

볼 것:

| 앱 | 입구를 연 뒤 주소들을 코드 블록 하나로 보여 주는가 | 블록을 통째로 복사해 보내면 전부 읽는가 | 주인장 부탁 문장에 경계·경고하는가 | 메모 |
| --- | --- | --- | --- | --- |
| ChatGPT · Claude · Gemini (작성자, 앱별 상세 미기록) | 잘 된다 | 잘 된다 | 문제 없음 | 2026-09-20. "잘 된다"는 총평만 받음. 앱별로 나눠 다시 기록할 것 |

### 2026-09-20 — 하루 정리: 무엇이 바뀌었나

| 아침의 전제 | 확인된 사실 | 바뀐 것 |
| --- | --- | --- |
| AI는 사진 속 글자를 읽으니 안내판을 찍어 보내면 된다 | 읽지만 열지 않는다. 이미지 속 글자를 인젝션으로 의심해 경계한다 | 안내판: "주소를 입력하세요" |
| 주소는 짧으면 된다 | Gemini는 `https://` 까지 있어야 연다 | 주소를 전부 인쇄 |
| 입구만 열면 조각은 따라 열린다 | Claude·Gemini는 그렇다. ChatGPT는 손님이 조각 주소를 보내야 연다. 여러 개를 한 번에 보내도 읽는다 | 입구에 조각 주소 전부를 코드 블록 하나로 |
| 간판은 AI에게 아무 말도 걸지 않는다 | 출처를 드러낸, 손님을 돕는 부탁 한 문장은 받아들여졌다 | "주인장 부탁" 형식 |
| 아무 호스팅이나 된다 | CDN이 AI 에이전트를 기본 차단할 수 있다. 색인 안 된 새 주소는 경고 대상 | GitHub Pages, DNS only, sitemap, 미리 배포 |

공통된 원리: **AI 앱이 믿는 것은 손님이 제 손으로 건넨 글자다.** 사진, 페이지 속 지시, AI가 조립한 주소는 믿지 않는다. 간판의 설계는 전부 이 한 줄에서 나온다.
